# T005_0 — Bulgu zenginleştirme (model)

Feature: [SP005](../features/SP005.md) · Repo: api-debug-agent

## Akış

```
detect() → List<Finding>          [SP004, deterministik — rapor burada tamamdır]
   │
   ├─ bulgu yoksa → model çağrılmaz, rapor döner
   │
   └─ FindingEnricher → tek model çağrısı → açıklama + öneri
         │
         └─ merge: yalnızca boş alanları doldurur
```

## Adımlar

1. `Finding`'e Java tarafında bir kimlik ver: `findingId` —
   `correlationId` + normalize sorgu hash'i. Model bunu geri döndürecek,
   eşleştirme bununla yapılacak.
2. `Finding`'e iki **nullable** alan ekle:
   ```java
   String explanation;      // model üretir
   FixSuggestion suggestion; // model üretir
   ```
   `record FixSuggestion(String action, String expectedResult, String risk, String alternatives) {}`
   Bunlar boş olduğunda rapor yine geçerli.
3. `llm/FindingEnricher.enrich(List<Finding>)`:
    - `llm.enabled: false` ise hiç çağırma, listeyi olduğu gibi dön
    - Liste boşsa çağırma
    - Tek model çağrısı; prompt `prompts/enrich.st`
4. Modele giden veri **yalnızca bulgu alanları**: findingId, endpoint,
   parentTable, childTable, foreignKey, normalizedQuery, repeatCount,
   distinctBindCount, confidence. Ham log yok.
5. Model çıktısı:
   ```json
   { "items": [
       { "findingId": "…",
         "explanation": "Müşteri listesi dönerken her müşterinin ödemeleri ayrı sorguyla çekiliyor.",
         "suggestion": { "action": "@EntityGraph(attributePaths = \"payments\")",
                         "expectedResult": "sorgu sayısı 214 → 2",
                         "risk": "…", "alternatives": "@BatchSize(size = 50)" } } ] }
   ```
6. **Merge tek yönlü:** yalnızca `explanation` ve `suggestion` doldurulur.
   Diğer hiçbir alana dokunma. `findingId` eşleşmeyen kalemler düşürülür ve
   sayısı loglanır — model uydurmuşsa rapora giremez.
7. Model çağrısını `try/catch` ile sar. Hata olursa logla ve **zenginleştirmesiz
   raporu dön**; analizi hataya düşürme.
8. Prompt'ta net ol:
    - "Sana verilen alanların dışına çıkma; tablo veya kolon adı uydurma"
    - "Sayıları değiştirme, yorumla"
    - "Fix'i uygulama, öner"
    - `expectedResult` somut sayı içersin
9. Bulgu sayısı 10'u geçerse en yüksek `repeatCount` olan 10'unu gönder;
   kalanlar zenginleştirilmeden raporda kalır.

## Doğrulama

- `llm.enabled: false` ile çalıştır → rapor tam, model hiç çağrılmıyor
- Modelin döndüğü bir `findingId`'yi elle boz → o kalem düşüyor, rapor sağlam
- `LlmClient`'ı hata fırlatacak şekilde mock'la → rapor yine dönüyor
- Bulgu yokken model hiç çağrılmıyor

## Tuzaklar

- Modelin metnini ölçüm alanlarının üstüne yazma. Merge tek yönlü olmalı;
  bu, algoritmanın güvenilirliğini koruyan tek şey.
- Modelin `isRealProblem` gibi bir karar alanı dönmesine izin verme — eleme
  yetkisi yok. "Bu meşru toplu okuma olabilir" diyecekse `explanation` içinde
  metin olarak söylesin.

## Kararlar

- **DTO adı `FixSuggestion` değil `FixProposal`, 5 alan:** `action`, `rationale`,
  `expectedResult`, `risk`, `alternatives`. `CLAUDE.md`'nin "Fix önerisi" bölümü bunu
  söylüyordu; task ve `contract.md` §5 ona hizalandı. Wire'daki alan adı `suggestion` olarak
  kaldı — console tarafında değişen tek şey içeriye eklenen `rationale`. `contract.md` üç
  repo'da ortak, `demo-api` ve `debug-console` kopyaları da güncellenmeli.
- **`findingId` hash'ine `foreignKey` de girdi.** Adım 1 "correlationId + normalize sorgu
  hash'i" diyordu, ama `NPlusOneDetector.detectInTemplate` aynı şablondaki her FK predicate'i
  için ayrı bir `Finding` üretiyor; iki bulgu aynı `correlationId` + aynı `normalizedQuery`
  ile çıkıp id çakışabiliyordu. Hash girdisi `correlationId|foreignKey|normalizedQuery`,
  SHA-256'nın ilk 12 hex karakteri.
- **`findingId` `Finding`'in içinde üretiliyor.** 12 argümanlı ikincil constructor id'yi
  kendisi hesaplayıp `explanation`/`suggestion`'ı `null` bırakıyor; `NPlusOneDetector`'a hiç
  dokunulmadı.
- **Tek yönlü merge `Finding.withEnrichment` içinde.** Birleştirme mantığı enricher'da değil
  record'da: ölçüm alanları aynen kopyalanıyor, dolu bir alan asla ezilmiyor.
- **`FindingEnricher` kendi `ObjectMapper`'ını kuruyor.** Boot 4 Jackson 3'ü autoconfigure
  ediyor, Jackson 2 `ObjectMapper` bean'i yok — `JsonResponseParser` ile aynı desen.
- **Prompt'taki örnek JSON `\{` / `\}` ile kaçırıldı.** `PromptLoader`'ın ST delimiter'ları
  `{`/`}`; kaçış olmadan şema örneği render'ı patlatıyor. `PromptLoaderTest` bunu doğruluyor.
- **Yakalanan tip `JsonProcessingException | RuntimeException`.** `backend-architecture.md`
  `catch (Exception)`'ı yasaklıyor; zenginleştirme yan kanal olduğu için hata yutuluyor ve
  gerekçe javadoc'a yazıldı.
- **Kapsam:** yalnızca zenginleştirme katmanı. `AnalysisService` / `AnalysisReport` yazılmadı;
  `FindingEnricher`'ın üretimde çağıranı henüz yok, doğrulama testlerle yapılıyor.
