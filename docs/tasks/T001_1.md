# T001_1 — Çok sağlayıcılı model erişimi

Feature: [SP001](../features/SP001.md) · Repo: api-debug-agent

## Adımlar

1. `llm/LlmClient` arayüze dönüşür; beton sınıf kalmaz.
   ```java
   public interface LlmClient {
       String provider();
       LlmResult ask(String promptName, Map<String,Object> vars);
   }
   ```
2. `llm/ChatClientLlmClient` (abstract) — ortak akış tek yerde: prompt render,
   `ChatClient` çağrısı, boş cevap/boş metin kontrolleri, `LlmResult`. Modele
   erişim ham `ChatModel` yerine `org.springframework.ai.chat.client.ChatClient`
   üzerinden. `ChatClient` `SingletonSupplier` ile ilk `ask()`'te kurulur;
   böylece model katmanı kapalıyken hiçbir `ChatModel`'e dokunulmaz.
3. `llm/AnthropicClient` — `provider()` → `anthropic`,
   `ObjectProvider<AnthropicChatModel>`, `AnthropicChatOptions.builder()`.
4. `llm/OpenRouterClient` — `provider()` → `openrouter`,
   `ObjectProvider<OpenAiChatModel>`, `OpenAiChatOptions.builder()`. OpenRouter
   OpenAI-uyumlu `/chat/completions` konuştuğu için ayrı bir istemci yazılmaz,
   base-url config'ten verilir.
5. `llm/RoutingLlmClient` (`@Primary`) — kayıtlı implementasyonları
   `provider()` adına göre haritalar, `llm.provider`'a göre delege eder.
   `llm.enabled` kontrolü **tek** burada; bilinmeyen sağlayıcıda
   `UnknownLlmProviderException`. Analiz katmanı yine sade `LlmClient` enjekte
   eder, hangi sağlayıcının aktif olduğunu bilmez.
6. Yeni exception'lar: `UnknownLlmProviderException`,
   `LlmProviderUnavailableException` (`ChatModel` bean'i yok ya da
   `llm.providers.<ad>.model` boş).
7. `llm/LlmProperties` sağlayıcı bazlı hale gelir:
   ```yaml
   llm:
     enabled: true
     provider: anthropic          # anthropic | openrouter
     providers:
       anthropic:
         model: claude-sonnet-5
         max-tokens: 3000
       openrouter:
         model: openai/gpt-5      # OpenRouter model kimliği: <sağlayıcı>/<model>
         max-tokens: 3000
   spring:
     ai:
       anthropic:
         api-key: ${ANTHROPIC_API_KEY:}
       openai:
         base-url: https://openrouter.ai/api/v1
         api-key: ${OPENROUTER_API_KEY:}
   ```
8. `pom.xml`: `spring-ai-starter-model-openai` (sürüm BOM'dan).

## Doğrulama

- `./mvnw test` — birim testleri + anahtarsız context testleri
- `ANTHROPIC_API_KEY` ile `LlmClientLiveTest`: gerçek çağrı, JSON parse
- `OPENROUTER_API_KEY` ile `OpenRouterClientLiveTest`: **yalnızca**
  `llm.provider=openrouter` değişikliğiyle aynı prompt farklı sağlayıcıdan döner
- Hiç anahtar yokken uygulama açılır; yalnızca `ask()` hata verir

## Tuzaklar

- `ObjectProvider<ChatModel>` **kullanılamaz**. Anthropic ve OpenAI
  autoconfig'lerinin ikisi de `spring.ai.model.chat` için
  `matchIfMissing = true` taşıyor; iki starter birlikteyken **iki** `ChatModel`
  bean'i oluşur ve `getObject()` `NoUniqueBeanDefinitionException` atar.
  Enjeksiyon beton tiplerle yapılmalı.
- `spring.ai.openai.api-key` **boş string** olarak verilmeli. Boş string
  bilinçli bir "no-auth" sinyali (Authorization header'ı sıyrılır); `null`
  kalırsa OpenAI SDK'nın credential doğrulaması açılışta patlar ve anahtarsız
  makinede context hiç açılmaz.
- `ChatClient`'ın `options(...)` metodu kurulmuş `ChatOptions` değil bir
  `ChatOptions.Builder` alıyor. Nihai options, `chatModel.getOptions().mutate()`
  üstüne `combineWith` ile bizim builder'ımız birleştirilerek üretiliyor —
  yani tip her zaman sağlayıcının kendi tipi oluyor. Bu şart:
  `OpenAiChatModel` içinde `(OpenAiChatOptions) prompt.getOptions()` şeklinde
  sert bir cast var, generic `ChatOptions` geçirilse `ClassCastException`.
- Sağlayıcı sızıntısı (`AnthropicChatOptions` / `OpenAiChatOptions`) yalnızca
  ilgili implementasyonda kalmalı; ortak taban sınıf `ChatOptions.Builder<?>`
  görür.

## Kararlar

- Seçim `@ConditionalOnProperty` ile değil `@Primary RoutingLlmClient` ile
  yapıldı: tüm implementasyonlar bean olarak durur, hangilerinin kayıtlı olduğu
  açılış logunda görünür, `llm.enabled` ve bilinmeyen-sağlayıcı hatası tek
  yerde toplanır, testte context yeniden ayağa kaldırmak gerekmez.
- Çağrı bazında model override'ı (`ask(..., provider)`) eklenmedi; SP001'in
  isteri "kod değişikliği olmadan değiştirilebilmeli", bu da config ile
  karşılanıyor. `ask()` imzası T001_0'daki gibi kaldı.
- `spring.ai.model.chat` set edilmiyor; iki `ChatModel` bean'i birlikte
  yaşıyor ve seçim `llm.provider` ile yapılıyor. İki ayrı anahtarın
  (`spring.ai.model.chat` + `llm.provider`) birbirine uyması gerektiği tuzağı
  böylece hiç doğmuyor.
- Yeni sağlayıcı `llm/` içinde flat duruyor, `llm/provider/` alt paketi
  açılmadı — CLAUDE.md'deki paket haritası `llm/` seviyesinde tanımlı.
- `ChatClientLlmClient`, `ChatClient`'ı `SingletonSupplier` ile tembel kuruyor;
  `ObjectProvider.getIfAvailable()` null dönerse `LlmProviderUnavailableException`.
  T001_0'daki "API key olmadan context açılır" garantisi korunuyor
  (`LlmDisabledContextTest`, `ApiDebugAgentApplicationTests`).
- `LlmProperties.providers` anahtarları küçük harfe normalize ediliyor;
  `llm.provider=OpenRouter` de çalışıyor.
- `LlmClientTest` → `AnthropicClientTest` oldu; yanına `OpenRouterClientTest`,
  `RoutingLlmClientTest` ve `LlmProviderContextTest` (primary bean router mı,
  iki sağlayıcı da kayıtlı mı) eklendi. `AnthropicChatModel`/`OpenAiChatModel`
  `final` sınıflar ama Mockito 5'in inline mock maker'ı ile mock'lanabiliyor;
  testlerde `getOptions()` stub'lamak zorunlu, çünkü nihai options oradan
  türetiliyor.
- OpenRouter üzerinden **gerçek** çağrı henüz koşulmadı: bu makinede
  `OPENROUTER_API_KEY` tanımlı değil. Kalan tek doğrulama adımı bu.
