# T12b — SQL ayrıştırma ve normalize

Feature: [SP003](../features/SP003.md) · Repo: api-debug-agent
Önceki: T003_0

Saf Java, HTTP yok, model yok. Birim testi kolay — algoritmanın doğruluğu
buraya bağlı, önce bunu sağlam yap.

## Adımlar

1. Bağımlılık: `com.github.jsqlparser:jsqlparser`.
2. `sqllog/SqlAnalyzer.parse(String sql)` → `ParsedSelect`:
   ```java
   record ParsedSelect(
       String table,              // FROM'daki ana tablo (alias çözülmüş)
       List<EqualityPredicate> parameterizedEqualities,
       boolean parsed             // ayrıştırılamadıysa false
   ) {}
   record EqualityPredicate(String table, String column) {}
   ```
3. Ayrıştırma kuralları:
   - `Select` değilse ele
   - `FromItem`'dan tablo adı ve alias'ı al; join varsa hepsini alias haritasına koy
   - `WHERE` içindeki `EqualsTo` ifadelerinden sağ tarafı `JdbcParameter` olanları
     topla — Hibernate `p1_0.customer_id=?` üretir
   - Sol taraftaki `Column`'un alias'ını haritadan gerçek tabloya çevir
4. `sqllog/SqlNormalizer.normalize(String sql)` → şablon:
   - Alias'ları kanonik hale getir (`p1_0.` → `t0.`, `c1_0.` → `t1.`) — Hibernate
     alias numaralarını statement'lar arasında değiştirebilir
   - Fazla boşlukları tekle, trim et
   - Küçük harfe çevir
   - Bind değerleri zaten `?` — ama sabit literal varsa onu da `?` yap
5. Ayrıştırılamayan SQL'de patlamа: `parsed=false` dön, o sorguyu analiz dışı
   bırak, sayısını rapora yaz.
6. Birim testleri — fixture olarak gerçek Hibernate SQL'leri kullan:
   - `select p1_0.id,p1_0.amount from payment p1_0 where p1_0.customer_id=?`
     → tablo `payment`, eşitlik `payment.customer_id`
   - Join'li ve alias'sız varyantlar
   - Aynı statement'ın iki koşusu aynı şablona düşüyor mu

## Doğrulama

- Fixture testleri yeşil
- Gerçek bir N+1 koşusunun tüm child sorguları tek şablonda toplanıyor
- Ayrıştırılamayan sorgu oranı %5'in altında

## Tuzaklar

- Alias normalize etmezsen aynı statement farklı şablonlara düşer ve tekrar
  sayımı çalışmaz. Bu, algoritmanın en kırılgan noktası.
- JSqlParser bazı Hibernate üretimi SQL'lerde takılabilir; `parsed=false` yolu
  gerçekten çalışsın, exception yukarı sızmasın.

## Kararlar

- Bağımlılık: `com.github.jsqlparser:jsqlparser:5.3` (Maven Central'daki güncel
  stabil sürüm, uygulama öncesi kullanıcı onayıyla eklendi).
- Visitor API'si generic: `ExpressionVisitor<T>`'in tüm `visit` metodları
  `<S> T visit(X x, S context)` şeklinde. `ExpressionVisitorAdapter<Void>`
  kullanıldı; yalnızca ihtiyaç duyulan `visit(Column, ...)` ve karşılaştırma
  operatörleri (`EqualsTo`, `NotEqualsTo`, `GreaterThan`, `GreaterThanEquals`,
  `MinorThan`, `MinorThanEquals`) override edildi, geri kalanı adapter'ın
  varsayılan özyinelemesine bırakıldı.
- WHERE ağacı gezimi **iteratif** (`ArrayDeque` tabanlı açık stack) —
  özyineleme kullanılmadı.
- FROM/JOIN alias haritası çıkarma mantığı `SqlAnalyzer` ve `SqlNormalizer`
  arasında paylaşılan paket-private `AliasedTable` record'unda toplandı.
- `SqlAnalyzer`: sadece en üst seviye AND zinciri (Parenthesis şeffaf geçilir)
  gezilir; `OR`/`IN`/diğer operatörler içine inilmeden sessizce atlanır.
  Alias'sız kolon, sorguda tek tablo varsa ana tabloya çözülür, yoksa atlanır.
  `ParsedSelect.table` ve `EqualityPredicate` alanları küçük harfe çevrilir
  (`ForeignKeyCache`'in küçük-harf anahtar sözleşmesiyle uyum için).
- `SqlNormalizer`: alias kanonikleştirme **ilk görünme sırasına göre
  pozisyonel** (`t0`, `t1`, ...) — Hibernate'in kendi numaralamasını taklit
  etmeye çalışmadan; yalnızca zaten alias'ı olan FROM/JOIN öğeleri yeniden
  adlandırıldı. Literal değerler (`LongValue`, `DoubleValue`, `StringValue`,
  `DateValue`, `TimeValue`, `TimestampValue`, `HexValue`) karşılaştırma
  operatörlerinde `JdbcParameter` ile değiştirildi; `NullValue` dokunulmadı.
  AST mutasyonu + `PlainSelect.toString()` ile render edildi — DeParser
  mekanizmasına girilmedi. Kapsam: WHERE, SELECT items, JOIN ON — GROUP BY /
  HAVING / ORDER BY bilerek kapsam dışı bırakıldı. Parse başarısızsa fallback:
  ham SQL'in lowercase/trim/whitespace-tekleme hali (regex tabanlı literal/
  alias tahmini yok).
- `%5 altında ayrıştırılamama` kabul kriteri otomatik test yerine demo-api
  ayaktayken gerçek bir N+1 senaryosundan alınacak loglarla elle
  doğrulanacak — henüz yapılmadı, SP003.md'deki ilgili kutucuk bu yüzden
  işaretlenmedi.
